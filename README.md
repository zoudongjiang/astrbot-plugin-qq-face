# astrbot_plugin_qq_face

让 AstrBot 机器人读懂用户的QQ表情、并能自己发出 QQ 原生小黄脸（OneBot v11 `face` 消息段）的插件。


很多机器人只能把 `[CQ:face,id=14]` 当成一行字发出去，也看不懂用户发来的表情。这个插件补上了两件事：

- **入站**：把用户发的 QQ 表情标注成可读文本，模型能知道对方发了「呲牙」；
- **出站**：模型写表情标记，插件把它换成真正的 `face` 消息段；分段回复时表情也不会被拆成单独一条消息。

## 功能

- 支持 `&#表情名#&` 写法（如 `&#呲牙#&`），也兼容 `[face:13]`、`[表情:13]`、`[CQ:face,id=13]`；
- 表情方案：多个方案自由切换，可全选 / 全不选 / 整包勾选 / 单个增删；
- 别名：给表情起更准确的名字（比如把「斜眼笑」叫「无语看戏」），提升模型选表情的准确率；
- 频率控制：每轮触发概率、单条上限、会话冷却、每小时上限；
- 提示词注入：按频率把「本轮必须发表情」的要求注入到本轮对话中，模板可编辑、可预览；
- 全部注入 / 随机 N 个两种注入方式；
- 设置页内置在 AstrBot WebUI，无需改配置文件。

## 环境要求

- AstrBot 4.17 及以上（推荐 4.29+）；
- 一个 OneBot v11 实现，并且：
  - 支持收发 `face` 消息段；
  - 支持 `fetch_sys_faces` 这个扩展 action（用于读取表情目录与名字）。
- 目前只在 **SnowLuma** 上验证过；其它实现如果满足以上条件，理论上也能用，但未验证。

没有 `fetch_sys_faces` 时会退回到内置的经典小黄脸表（0–104），功能仍可用，只是可选表情少一些。

## 安装

1. 把整个 `astrbot_plugin_qq_face` 目录放到 AstrBot 的插件目录：
   - 源码部署：`<AstrBot 根目录>/data/plugins/`
   - 启动器部署：在启动器的实例目录下找到 `core/data/plugins/`
2. 打开 AstrBot WebUI → 插件 → 找到「QQ 原生表情」→ 重载；
3. 进入插件 → 视图 → **QQ 表情配置**。

不需要额外依赖，也不用改 `cmd_config.json`。

## 快速开始

1. 在「表情方案」里保留或调整默认方案（默认 16 个常用小黄脸）；
2. 在「提示词」里确认注入方式（全部 / 随机 N 个）与文案；
3. 在「出现频率」里设置每轮触发概率（默认 50%）与上限；
4. 保存后，在 QQ 里让机器人发表情即可看到效果；
5. 想手动验证：发送 `/表情 13` 或 `/表情 呲牙`。

## 表情写法

推荐用名字或别名：

```text
今天不想上班 &#呲牙#&
```

也兼容：

```text
[face:13]  [face:呲牙]  [表情:13]  [CQ:face,id=13]
```

解析不到的名字会被丢弃，只保留文字；别名与原名都可用于解析，别名优先。

## 设置项

| 设置 | 说明 |
| --- | --- |
| 触发方式 | 提示词模式；情感识别模式为预留项，暂未实现 |
| 表情方案 | 多方案切换，支持新建 / 重命名 / 删除 |
| 允许方案外表情 | 开启时，目录里存在但不在当前方案里的表情也放行（模型凭记忆使用其它表情时的兜底） |
| 别名 | 每个已选表情可设置别名，提示词与标记都会使用别名 |
| 注入方式 | 全部注入，或每轮随机抽 N 个（默认 12） |
| 提示词 | 可编辑模板，支持 `{max}`、`{faces}`、`{packs}` 变量；留空使用默认 |
| 预览 | 按当前表单实时渲染，和实际注入内容一致 |
| 每轮触发概率 | 每轮对话打开「表情窗口」的概率，默认 50% |
| 每次最多发 | 单条回复最多保留几个表情（0–5） |
| 冷却 | 同一会话两次发表情的最小间隔（秒） |
| 每小时上限 | 全局每小时上限（0 为不限） |

设置保存在 AstrBot 的插件 KV 存储中，重载插件不会丢失。

## 工作原理

- **入站**：`event.message_obj.message` 里的 `Face` 组件被转成 `[表情:呲牙(id=13)]` 写回 `message_str`，同时避免「纯表情消息被当成空消息跳过」；
- **注入**：每轮按频率决定是否注入；命中时把要求放进本轮用户消息之后的 `extra_user_content_parts`（临时内容，不写入历史），比放在 system prompt 里更容易被模型执行；
- **出站**：发送前把标记换成 `Face` 组件；标记在文本里会先被挪到标点前，避免被分段回复切走；
- **兜底**：模型用了方案外但目录里存在的表情时，默认放行（可在视图关闭）。

## 常见问题

**机器人还是只发文字？**

- 确认插件已启用并重载；
- 确认「每轮触发概率」不是 0；
- 如果开了流式回复，`on_decorating_result` 不会执行，表情标记会以文字形式漏出去，需要关闭流式；
- 查看提示词预览，确认模型确实拿到了表情列表。

**表情变成 `&#xxx#&` 原文？**

说明标记没有被解析：检查名字是否在方案里（或开启「允许方案外表情」），以及是否被别的插件改写了消息链。

**数字表情 ID 对不上？**

不同协议端对 `face` 段的 id 可能不同；本插件优先按名字解析，名字来自 `fetch_sys_faces` 目录。

## 目录结构

```text
astrbot_plugin_qq_face/
├─ main.py                 # 插件入口：钩子、策略、Web API
├─ policy.py               # 设置模型与频率策略
├─ prompt_builder.py       # 提示词模板与渲染
├─ catalog.py              # 表情目录获取与兜底
├─ face_utils.py           # 表情名表、标记解析、文本归一化
├─ metadata.yaml
├─ views/face-settings/    # 设置页（HTML / CSS / JS）
├─ .astrbot-plugin/i18n/   # 视图标题等文案
└─ tests/                  # 纯逻辑与发送链路测试
```

## 开发

```bash
python tests/test_policy_and_text.py   # 设置、策略、标记、提示词
python tests/test_send_path.py         # 发送链路（用轻量替身模拟 AstrBot）
```

两个脚本不依赖 AstrBot 运行环境，改完逻辑可以直接跑。
